対象ホール: ガーデン川口安行

## 横展開候補（越谷近隣、2026-08-21調査）
同じ仕組み（イベシル/いけちんの晒し＋athink実データ）がそのまま使えるのはガーデングループのみ（athink.jpはガーデン専用データサイト）。越谷からの近さ順:
1. **ガーデン八潮** tenpo_id=yashio — イベシル店別結果あり（列全・12台並びまで記載）、いけちん来店取材対象
2. ガーデン川口安行 tenpo_id=angyou — 稼働中
3. ガーデン東浦和 tenpo_id=higashiura
4. ガーデン春日部 tenpo_id=kasukabe
横展開はcollectorとindex.htmlのtenpo_id/店名を差し替え（またはパラメータ化）すれば動く。非ガーデン店（越谷市内のマルハン等）はathink非対応のため実データ照合ができず対象外（サイトセブン導入とセットで再検討）

## 必須ルール
1. **イベシルの詳細画像ポストは絶対に取り逃さない。** 店名付きで定期発表される。画像URL（pbs.twimg.com/media/…）を posts_raw.json に保存し、画像から台番・機種名・G数・差枚を読み取って events.json の `dai_detail` に反映する（columns: [台番, G数, 差枚]）。画像はURL失効に備えて data/kuse/img/{date}_{n}.jpg にも保存する
2. 結果ポストは前日ヒントを引用していることが多い。引用先IDも記録する
3. 原文は必ず posts_raw.json に残す（構造化に失敗しても後で再パースできるように）

## 運用（2026-08-21決定）
- **手動トリガーのみ**（定期実行なし）。ユーザーが「くせ読み更新して」等と言ったときに収集する。打ちに行く前日/当日朝の依頼を想定
- 収集時は主要2アカウントに加えて、**`ガーデン川口安行 M/D` の全体検索**（例: `ガーデン川口安行 8/21`）で他のアカウントの晒し・実戦報告も拾う。有望なアカウントを見つけたら本ファイルの情報源に追記する

## 収集方法（検証済み 2026-08-21）
- 検索: `from:eveshiru 安行` / `from:ikechinpachislo 安行` ＋ 全体検索 `ガーデン川口安行 M/D` を「最新」タブで。期間指定は `since:YYYY-MM-DD until:YYYY-MM-DD`
- **Xの検索はすぐスロットルされる**（結果の間引き→空、内部APIは404）。1晩の収集は検索2〜3回＋新規ポストの個別ページ閲覧数件に留める。個別ポストページ（/status/ID）はスロットル対象外で安定
- 機種名を正しく取るためXの表示言語は日本語のままにする（英語だと自動翻訳で機種名が壊れる。lang=jaパラメータでは回避不可）
- DOM抽出: `article[data-testid="tweet"]` 内の `[data-testid="tweetText"]`、`time[datetime]`、`img[src*="pbs.twimg.com/media"]`。タイムライン表示は長文が省略されるので、全文は個別ページで取る
